# BYD Dolphin Auto Assistant v30

BYD DiLink 3.0 차량용 보조 앱의 v30 정리본입니다. 제공된 차량 감사 자료와 `framework.jar`에서 확인한 메서드·상수만 차량 제어 경로에 사용하며, 확인되지 않은 브로드캐스트와 임의 장비 패킷은 차단합니다.

## v30의 핵심 원칙

- 차량 제어는 BYD SDK 호출의 반환값을 확인하고 가능한 항목은 getter로 재확인합니다.
- 비상등처럼 getter만 있고 공개 setter가 없는 기능은 자동 명령을 보내지 않습니다.
- BSD·차선·AVH·주행모드·회생제동은 원시값을 기록하되, 실차 의미가 매핑되기 전에는 자동 음성을 내지 않습니다.
- 계기판은 작은 TBT 화살표·거리·도로명만 지원합니다. 전체화면 미러링은 제외했습니다.
- 사용자 제공 본체 라벨에서 장비를 `TMAP Plus HUD / T900`(제조사 주식회사 인포라텍, KC `R-R-9IT-JARVIS3000`)으로 확인했습니다. 모델은 확정됐지만 펌웨어별 바이너리 프로토콜은 아직 확인되지 않아 SPP/UUID 진단만 하며 데이터·오디오·밝기 패킷은 보내지 않습니다.
- 3·4분할은 DiLink 3에서 재현 가능한 명령 흐름을 확보하지 못해 제외하고, 검증 가능한 2분할만 제공합니다.

## 구현 범위

### 차량 상태와 편의 기능

- 시동: `BYDAutoBodyworkDevice.getPowerLevel()`의 0/2 전환을 연속 확인하고 시동 주기당 한 번만 자동 실행
- 속도·기어: `getCurrentSpeed()`, `getCurrentGear()` 폴링
- EPB·충전: `getEPBState()` 전환 및 `getChargerWorkState()`의 시작·정상 완료 음성(중단 상태는 완료로 안내하지 않음)
- 공조: 전원, 0~7단 풍량, 앞·뒤 성에 제거
- 열선: 운전석·동승석 0~2단, 핸들 열선
- 조명: 전체 실내등 켜기/끄기 및 도어 연동 상태
- 전방 출발 후보: 내비 알림 문구 및 사용자가 직접 켠 경우에만 유효한 정차 속도와 전방 주차센서를 함께 확인하는 실험 기능

### 화면·앱 자동화

- 서로 다른 두 앱의 2분할 실행, 20~80% 범위에서 1% 단위 저장·복원
- AVM 종료 후 마지막 2분할 구성을 복원하고 전체 명령 결과를 진단 로그에 기록
- 시동 ON 뒤 여러 앱을 앱별 0.1초 단위로 실행
- 각 앱마다 미디어 PLAY 사용 여부와 앱 실행 후 재생 지연을 별도로 설정

### 플로팅 독과 바로가기

- 실제 런처 앱 전체 검색 및 실제 앱 아이콘 표시
- 한 화면 최대 8개, 9개부터 가로 스크롤
- 크기·투명도·자동 접기 시간·위치 조절, 길게 눌러 항목 제거
- 일정 시간 뒤 작은 손잡이로 접히며 터치 시 복원
- 런처가 지원하면 홈 화면 고정 바로가기 생성
- 외부 앱이 차량 바로가기 액티비티를 임의 호출하지 못하도록 설치별 토큰 검증

### 내비·계기판·오디오

- BYD TMAP 변형, 모바일 TMAP, 네이버지도, 카카오내비, 아이나비 에어 알림 후보 지원
- `BYDAutoInstrumentDevice.sendAutoNaviStatus()`, `sendSimpleGuidanceInfo()`, `sendNextPathName()` 사용
- TTS는 `USAGE_ASSISTANCE_NAVIGATION_GUIDANCE`로 출력하며 실제 물리 스피커 존은 BYD 오디오 정책에 위임
- v30.2의 **운전석 오디오 4경로 비교 테스트**는 표준 NAV AudioTrack, 커뮤니티 SoundPool NAV/SPEECH, legacy-attribute stream 14, 레거시 AudioTrack stream 14를 순서대로 비교하고 `AUDIO_PROBE` 진단을 남김
- 실차 경로가 확인되기 전에는 일반 TTS/BSD/차선 경고의 기본 출력을 stream 14로 강제 변경하지 않음
- 알림 접근 서비스와 사용자가 직접 켜는 보조 접근성 입력 제공

### 앱 자체 원터치 진단

- **DPI & 원터치 진단 → 15분 수집 시작** 한 번으로 앱 내부 동작과 오류를 시간순 `events.jsonl`에 기록
- BYD 공개 getter의 차량 원시값을 2초마다 읽어 값이 바뀐 순간만 기록하고, 차량 제어 setter는 호출하지 않음
- T900을 포함한 페어링 기기 이름·마스킹 주소·프로필 UUID와 연결/해제/본딩/SDP 이벤트 기록
- 실차에 존재하는 BYD 공개 메서드 서명을 실행 없이 조사해 `framework_methods.txt`로 보존
- 권한, 차량 OS/펌웨어 식별 정보, 기능 상태, 최근 앱 로그와 접근 가능한 logcat을 함께 ZIP 하나로 내보냄
- 앱이 비정상 종료돼도 다음 실행에서 미완료 세션을 복구해 내보낼 수 있음
- 내비 알림 원문은 기본적으로 저장하지 않고 길이와 SHA-256 일부만 기록. 화면에서 명시적으로 켠 경우에도 해당 15분 세션 동안만 원문 허용

일반 버그 재현에는 스마트폰 버그제거 앱이나 ADB가 필요하지 않습니다. 앱은 Android 보안상 Bluetooth HCI 원시 패킷, 다른 앱의 비공개 로그, root/시스템 서명 전용 정보까지는 읽을 수 없습니다.

## 안전 기본값

- 계기판 TBT: OFF
- 시동 자동 실행: OFF
- 실험적 주차센서 전방 출발 후보 감지: OFF
- 티맵 Plus HUD 패킷 송신: 소스 수준에서 잠금
- 진단 내비 알림 원문: OFF
- 비상등 자동 명령: 소스 수준에서 차단
- 미확인 전동시트·미러·창문·외부 스피커 제어: 미포함

## 빌드

필요 환경은 JDK 17, Android SDK 34, 인터넷 연결입니다.

```bash
./gradlew :app:assembleDebug
```

생성 위치:

```text
app/build/outputs/apk/debug/app-debug.apk
```

저장소에 포함된 GitHub Actions 워크플로를 사용하면 `DolphinAutoAssistant-v30-Debug` 아티팩트로 받을 수 있습니다.

## 설치 후 필수 확인

1. Android 13 이상이면 알림 권한을 허용합니다.
2. 플로팅 독을 사용할 경우 다른 앱 위에 표시 권한을 허용합니다.
3. 계기판 TBT를 사용할 경우 알림 접근 또는 보조 접근성 브릿지 중 하나를 사용자가 직접 켭니다.
4. TMAP Plus HUD / T900 연결 진단을 할 때만 근처 기기 권한을 허용합니다.
5. 기존 v29 고정 바로가기는 보안 토큰이 없어 차단되므로 v30에서 다시 만듭니다.
6. 앱의 **DPI & 원터치 진단 → 15분 수집 시작**을 누르고 문제를 재현합니다. 문제가 보인 순간 **문제 순간 표시**를 누른 뒤 **수집 종료 + ZIP 내보내기**로 생성된 ZIP 하나를 공유합니다.

> BYD 서명 권한 승인 여부와 계기판 표시 수용 여부는 차량 펌웨어·화이트리스트에 따라 달라질 수 있습니다. 버튼의 성공 문구보다 생성된 v30 진단 ZIP의 권한/반환 코드를 기준으로 판단하십시오. 로컬 ADB는 DPI·특수 권한처럼 ADB 전용 기능을 처음 준비할 때만 별도로 필요할 수 있습니다.
